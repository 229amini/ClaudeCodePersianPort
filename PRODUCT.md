# Product

## Platform

web

## Users

Two audiences, one per edition (confirmed 2026-10-07):

- **Web edition** (`persian-claude-gui/static/`): a non-technical Persian speaker who must never
  touch a terminal. The original user is the owner's colleague, who has run it daily since early
  August 2026. They read Persian, ask Claude Code to do real work on their PC, and approve or deny
  what it wants to do.
- **Terminal edition** (`persian-claude-gui/static-terminal/`): a Persian-speaking developer who
  uses Claude Code every day and knows the TUI — its key chords, `/` commands and wording. Often
  runs several conversations side by side (1 to 6 panes).

Both editions are public (GitHub, MIT) and meant to be announced to Persian-speaking Claude Code
users generally.

## Product Purpose

A Persian, fully right-to-left front-end for the real Claude Code CLI on Windows. Windows
terminals cannot shape Persian, reorder mixed Persian/English lines, or type a half-space
(ZWNJ); a browser engine can. The window replaces only the screen: the official `claude` runs
underneath unmodified, with the user's own login, settings, skills and hooks.

Success: a Persian speaker does real work with Claude Code without a terminal, and every
sentence — including file paths, commands and code inside Persian text — reads in the right
order.

## Positioning

It is the real Claude Code, not a reimplementation or an API client: same subscription, same
`~/.claude`, same features, in a window that gets Persian right. Nothing is sent anywhere but the
CLI's own traffic; the server listens on `127.0.0.1` only.

## Operating Context

- Windows 10/11, Microsoft Edge in app mode (a chrome-less window), launched from a desktop
  shortcut that `setup.bat` writes. The target PC may be offline or locked down.
- Long sessions: conversations last hours, run tools, ask for permission, and are resumed later.
- Users switch between projects (folders) and conversations from a sidebar.
- The colleague-facing guide is `static/help.html`; it is the only documentation that audience
  reads.

## Capabilities and Constraints

- Server: Python 3.12 stdlib only. Frontend: vanilla HTML/CSS/JS, no build step, no npm, no CDN.
  Fonts (Vazirmatn) and `marked` are vendored.
- Persian UI: every user-visible string lives in `strings.fa.js` per edition.
- BiDi discipline is binding: `claude-persian-rtl-spec.md` (base CSS, rules 1–7) is the
  contract. The shell is `dir="rtl"`; every content-bearing element carries its own direction;
  Windows paths always render LTR and isolated (`.path`).
- Feature parity with the CLI is the goal: permissions (four postures), AskUserQuestion forms,
  plan mode, message queue, slash commands, model/effort/output style, context and usage panel,
  sessions with search, rename, pins and fork, multi-pane grid.
- Unknown CLI stream events render as a collapsed raw-JSON card, never a crash.
- Shared files must stay byte-identical across editions (`tokens.css`, `bar.js`, `marks.js`,
  `focus.js`).

## Brand Commitments

Confirmed by the user 2026-10-07:

- **Claude orange is the primary accent** (`#d97757`; `#b5552f` as a fill under white text). Not
  VS Code blue — a blue accent was tried in the redesign and rejected.
- **Calm, quiet tool.** Restraint over spectacle; this is a working tool used for hours.
- **Recognisably Claude Code.** Someone who knows Claude Code — the VS Code extension webview and
  claude.ai/code in particular — should recognise it at once. The extension's webview
  (`wiki/vscode-webview-design.md`) is the reference the current redesign was measured from.
- **Dark theme only.**
- Name: «کلاد فارسی» (web), «کلاد فارسی — ترمینال» (terminal edition).

## Product Principles

1. The CLI is the product; the window is a faithful screen for it. Never hide or reinvent what
   the CLI does.
2. Persian reads right first. A layout that breaks a mixed line is a defect, whatever it looks
   like.
3. The person decides. Permission requests and questions wait for them and are never answered
   silently.
4. Calm under load: long transcripts, many panes and streaming text must stay legible and still.
5. Measured, not eyeballed: every visual claim is checked by a headless gate or `audit_ui.py`.

## Accessibility & Inclusion

Current practice (not separately confirmed): WCAG AA — 4.5:1 text contrast, 24×24 px targets,
visible focus — measured by `persian-claude-gui/audit_ui.py`. Persian-bearing text never below
12 px (Vazirmatn is unreadable smaller); body text 14 px with line height ≥ 1.9.
